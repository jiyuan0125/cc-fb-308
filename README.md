# 交易明细质量管道

从 `batches/` 读取财务交易明细批次 CSV，按 `rules.yaml` 执行质量检查：坏行隔离
到 `quarantine/`，合格批次入库 SQLite，整批不可信时整批拦截并停下等人修数；
重跑自动跳过已通过的批次，每轮输出 `quality_report.txt`。

环境：Python 3 + pandas + PyYAML + SQLite（标准库），不使用 Docker。

## 快速开始

```bash
python3 pipeline.py
```

默认使用仓库根目录下的相对路径：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--rules` | `rules.yaml` | 规则清单 |
| `--batches` | `batches` | 批次 CSV 目录（按文件名排序处理） |
| `--db` | `warehouse.db` | SQLite 数据库 |
| `--report` | `quality_report.txt` | 每轮质量报告 |
| `--quarantine` | `quarantine` | 行级不合格记录的隔离目录 |
| `--log-level` | `INFO` | 日志级别（日志输出到 stderr） |

依赖安装（如本机没有）：

```bash
uv pip install pandas pyyaml    # 或 pip install pandas pyyaml
```

## 仓库结构

```
batches/            样例批次（12 个 CSV）
rules.yaml          质量规则清单
pipeline.py         管道实现
tests/              pytest 用例
quarantine/         运行时生成：行级不合格记录
warehouse.db        运行时生成：SQLite 入库库
quality_report.txt  运行时生成：每轮质量报告
```

## 规则配置

`rules.yaml` 结构如下，程序逐条解释，不认得的规则直接报错退出（不会静默跳过）：

```yaml
规则清单:
  - 规则名: 金额为正
    字段: amount
    要求: 严格大于
    界限值: 0
```

支持以下判据（按判据语义决定检查层级）：

| `要求` / 字段组合 | 检查层级 | 判定 | 归类理由 |
|---|---|---|---|
| `严格大于` + `界限值` | 逐行 | 字段转数值后严格大于界限值 | 判据只看单行 |
| `取值属于` + `允许值` | 逐行 | 字段值属于给定列表 | 判据只看单行 |
| `首字符` + `后续字符` + `后续位数` | 逐行 | 按字符类别生成格式匹配 | 判据只看单行 |
| `批内不重复` | 整批 | 批内该字段值有重复即命中 | 要对批内多行比对，无法判定哪一行是坏行 |
| `合计不超过` + `上限` | 整批 | 批内字段（数值）合计超过上限即命中 | 依赖全批汇总 |

格式规则的取值是封闭枚举：`首字符` / `后续字符` 支持 `英文字母`、`字母`、
`数字`、`字母或数字`；`后续位数` 为非负整数。例如样例中的账户规则会解析成
`[A-Za-z][0-9]{10}`。

金额一律用 `Decimal` 解析与汇总，避免浮点误差；无法解析的金额按“不满足
严格大于”隔离，并在计算批合计时跳过（日志里有 WARNING 提示）。

## 处理语义

### 逐行规则：坏行隔离，不连累整批

命中逐行规则的行写入 `quarantine/<原批次文件名>`，同批其余行正常入库。隔离
文件保留原始 6 个字段，并追加两列：

- `违规规则`：命中的规则名，多条用 `; ` 分隔，按规则清单顺序；
- `数据行号`：数据行的序号（表头不算，从 1 起）。

一条行可同时命中多条规则，因此“各原因计数”之和可能大于隔离行数。

### 整批规则：整批不可信，拦截并停下

任一整批规则命中时：

- 本批**全部行不入库**，也不写隔离文件（隔离只用于“整批可信但个别行有问题”的场景）；
- 运行在**当前批次停下**，后续批次本轮不处理（等待人工修数）；
- 命中信息写入报告，数据库记录该批 `status = failed`、`failure_reason`。

人工修好后重新运行即可：已通过批次跳过，从失败的那批继续；修复后的批次若
仍不合格，会再次拦截，直到通过。

### 结构性校验（与业务规则无关，命中即整批失败）

- CSV 无法解析、文件为空、没有数据行；
- 表头缺必需字段（基础字段 + 规则引用到的字段）或存在重复列名；
- `batch_id` 列不是唯一一个非空批号；
- `txn_id` 为空（无法唯一标识行）。

这些情况同样按“整批不可信”处理并中断。批号无法从数据中取得时，用文件名兜底
（`batch_xxx.csv` 取 `xxx`）。

### 断点续跑

- 每批的数据、隔离行、规则命中、批次状态在**同一个 SQLite 事务**里提交，
  进程中断或整批失败都不会留下半批数据；
- 重跑时按 `batch_id` 查询已通过的批次并直接跳过，不重复入库；
- 失败批次（含上次中断时未提交的批次）会重新判定；
- 已通过批次即使文件内容后来被改动也不会重跑，只记一条 WARNING（入库时保存
  了文件 SHA256 用于提示）；这是“已经通过的批次不要重来”的直接落实。

## 输出

### `warehouse.db`

| 表 | 内容 |
|---|---|
| `transactions` | 已入库的行（原始字段按文本保存），主键 `(batch_id, row_no)` |
| `quarantined_rows` | 被隔离的行 |
| `row_rule_hits` | 行级规则命中明细，供规则视角统计 |
| `batch_rule_hits` | 整批规则命中（含涉及行数） |
| `batches` | 每批状态、行数、失败原因、文件 SHA256 |

`quarantine/` 下的文件每轮从数据库重建（原子写入），保证文件与库内状态一致。

### `quality_report.txt`

每轮覆盖写入，包含两个视角：

- **按行视角**：读取行数、合格数（已入库行数）、隔离数、整批失败未入库行数、
  各原因计数；
- **按规则视角**：每条规则（含零命中）的类型、命中批次数、命中行数；
- 另有本轮概况、批次明细、累计视图（数据库内全部批次）。

统计口径：

- 行视角只把**整批通过**批次中被隔离的行算作“隔离数”；整批失败批次的全部行
  计入“整批失败未入库行数”，两者不重叠，读数相加等于读取行数
  （结构性失败无法可靠读行，按 0 计）；
- 规则视角的“命中”包含整批失败批次中已检出的行级问题，因此可能大于隔离数；
- 整批规则的命中行数取该规则涉及的行数：交易号重复取涉重复的行，合计超限取
  整批行数；
- 累计视图按数据库当前状态统计：失败后修好并通过的批次不再计为规则命中，
  历史每轮命中情况见当轮报告。

## 退出码

| 退出码 | 含义 |
|---|---|
| 0 | 全部批次通过（或本次没有待处理批次） |
| 1 | 规则配置/运行环境错误（未处理任何批次） |
| 2 | 有批次整批不合格，运行已中断，等待修数 |
| 130 | 进程被中断（已提交批次保持入库） |

## 样例数据

`batches/` 共 12 批 473 行：

- `batch_20260301` 至 `batch_20260306`：干净批次；
- `batch_20260307`：2 行金额为负或为零（行级隔离）；
- `batch_20260308`：2 行币种为 HKD/SGD（行级隔离）；
- `batch_20260309`：2 行账户格式不合规（行级隔离）；
- `batch_20260310`：交易号 `T10000384` 重复（整批拦截）；
- `batch_20260311`：批内合计 369542.13 超过上限 300000（整批拦截）；
- `batch_20260312`：交易号 `T10000453` 重复（整批拦截）。

首轮会通过 301-309（369 行入库、6 行隔离），停在 310；修数后逐批续跑。

## 已知边界

- 交易号唯一性只按批次约束（规则原文是“批内不重复”），不检查跨批次重复；
- 批合计按原批全部可解析金额汇总（含负数），不是“隔离后实际入库金额”；
- 已通过批次不因规则变化重跑，重新判定需要用新数据库重跑；
- 同一个 `batch_id` 出现在两个不同文件名下视为环境冲突，运行直接报错退出（1）；
- 不提供跨批次交易号查重、金额精度外的对账、人工审核界面。
