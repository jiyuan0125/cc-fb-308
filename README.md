# 交易明细质量管道

财务交易明细按批次 CSV 到达 `batches/`，入库 SQLite 前按 `rules.yaml` 中的规则做数据质量检查。

## 运行

```bash
python3 pipeline.py        # 在仓库根目录运行
python3 -m pytest -q       # 运行测试
```

依赖：Python 3 + pandas + PyYAML（SQLite 为标准库）。

## 处理语义

- **行级规则**（金额为正、币种在支持列表、账户格式合规、批内交易号唯一）：
  个别行的毛病，坏行写入 `quarantine/batch_<批次号>.csv`（附 `不合格原因` 列），
  不连累整批，合格行正常入库。批内重复 txn_id 保留首次出现，后续重复行隔离。
- **批级规则**（单批合计不超风控上限）：命中说明整批不可信，本批**全部不入库**，
  状态记为 `failed`，本轮运行立即停止，等人修数。
- **断点续跑**：状态持久化在 `pipeline.db`（表 `batches` / `transactions`）。
  再次运行时，已 `loaded` 的批次跳过不重跑、不重复入库；`failed` 及未处理的批次
  从失败的那批起继续处理。每个批次的入库与状态更新在同一事务内提交，中断不会
  留下半截批次。
- 每轮运行结束输出 `quality_report.txt`：
  - **行视角**：合格入库行数、隔离行数、各原因（行级规则）隔离计数；
  - **规则视角**：每条规则命中的批次数和行数；
  - 附批次明细（入库/隔离/失败/跳过）。

退出码：正常完成（含全部跳过）为 0；因整批失败而停跑为 1。

## 规则配置

`rules.yaml` 的 `规则清单` 是检查口径的唯一来源，程序按规则语义自动归类执行：

| 规则特征 | 归类 | 含义 |
|---|---|---|
| `要求: 严格大于` + `界限值` | 行级 | 数值字段严格大于界限（非数值视为不合格） |
| `要求: 取值属于` + `允许值` | 行级 | 字段取值须在允许列表内 |
| `首字符`/`后续字符`/`后续位数` | 行级 | 账户格式（首字符英文字母 + 固定位数数字） |
| `要求: 批内不重复` | 行级 | 字段值在批内唯一 |
| `要求: 合计不超过` + `上限` | 批级 | 字段合计不超风控上限 |

调整阈值、允许值列表等只需改 `rules.yaml`，无需改代码。

## 样例数据的预期行为

`batches/` 共 12 批（20260301–20260312）：

- 0307/0308/0309/0310 含行级问题（金额非正、币种越界、账户格式错、txn_id 重复），
  坏行进 `quarantine/`，其余入库；
- **0311 合计超风控上限**，整批失败，首轮运行停在该批，0312 暂不处理；
- 修好 0311 的数据后再次运行：01–10 跳过，从 0311 继续，0312 随之入库；
- 全部通过后再次运行：12 批全部跳过，幂等无副作用。
